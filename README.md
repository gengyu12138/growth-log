# 成长记录

给一个家庭用的孩子成长记录小程序。微信原生开发 + 云开发，无自建服务器。

记的不是流水账，是**节点**。判断一个功能要不要做，只问一句：三年后想问「她第一次发烧是哪天」，这个功能能不能答上来。

## 设计取舍

做这类工具最容易踩的坑是把「记录」做成「打卡」——要求每天写，第三周就断更，然后整个应用死掉。

所以这个项目主动砍掉了这些东西：

| 不做 | 原因 |
|---|---|
| 每日日记式记录 | 靠自觉每天写必然断更 |
| 分类统计饼图 | 成长记录不需要「日常占比 23%」这类图表 |
| 共享日历 | 系统日历已支持共享与提醒，做不过它 |
| 实时协作 | 两人都是新增记录，最后写入为准即可 |
| 按天强制归档 | 一天可以没有记录，这不叫漏记 |

留下的只有三件事：**随手记一条**、**按时间翻回去看**、**问一句能从历史里答上来**。

## 功能

- **记录**：首页底部直接输入，默认点击语音，一键切键盘；转写自动整理，核对后保存，重要日期或数量冲突才追问
- **时间轴与月历**：主页默认左侧时间轴与紧凑内容，详情按需展开；日历可切换，计划单独查看
- **Tab 切换**：保留已访问页面与滚动位置，已有内容保持可见并在后台刷新
- **动态卡片**：AI 按原文选择文字、数值、区间、里程碑、健康或清单布局；照片自动排版，原文与依据可展开，旧记录无需重算
- **搜索**：单字关键词和筛选不消耗模型额度；可单独用 AI 理解“第一次爬是哪天”等问题，完整检索原记录，日期结果附来源
- **待同步与草稿**：多份草稿按账号与家庭隔离；确认保存先落本机，联网核对身份后沿用固定提交标识同步，结果不确定时可核对原提交
- **成长专题**：关键词或手选原记录，按时间串联一件事的变化；新匹配记录自动纳入，云端同步复用个人关注项
- **重复核对**：同日相似原文或相同照片提示；可以保留两条，也可核对合并预览，保留第一条并将第二条移入回收站
- **照片理解**：首页或编辑页新增照片后自动看图；生活照描述可见动作，截图、报告等提取文字与数值，核对采用后整理卡片；复用已有 DeepSeek Key，不自动把照片状态标成“第一次”
- **照片导入**：可单独选择智能识图，将描述及文字带入首页；手写/密集文字另有可选专用 OCR，需单独配置
- **图片**：每条最多 9 张，支持编辑时补充照片与按月浏览照片回忆
- **编辑**：阅读与编辑分开，本机编辑草稿恢复，重新整理卡片后确认保存，保留版本冲突检查
- **语音（可选）**：最长 60 秒，转文字后自动调用已有 AI 分析，核对后才保存；需单独配置语音服务
- **成长档案**：昵称、生日等基础信息
- **成长月记**：按月汇总普通记录、第一次、珍藏和照片，可整理成长故事；无同日回忆时展示同月片段
- **收藏**：把里程碑单独标出来，和「第一次」一起成为月记的候选
- **AI 助手**：看板、追踪、补全追问、纠错、成长故事、前后对比六种意图；关注项按账号和家庭同步（需新版云函数）
- **家庭成员**：邀请码加入，`owner` / `editor` / `viewer` 三级权限，viewer 只读
- **回收站与操作历史**：删除后可直接撤销，软删除可还原；合并与修改均留审计事件
- **成长册与导出**：可按年度、生日年或自选日期选取记录和照片，编辑封面、章节与寄语；生成可阅读/打印的 HTML 或含照片 ZIP，兼容原 JSON 完整备份

事件有明确时刻时优先显示事件时刻；否则显示首次保存时的钟点。补记仍保留选择的事件日期，历史记录不会刷新成当前时间。

## 技术栈

| 层 | 选型 |
|---|---|
| 客户端 | 微信小程序原生（JavaScript / WXML / WXSS），无构建流程 |
| 后端 | 微信云开发：云函数 + 云数据库 + 云存储 |
| 鉴权 | `openid`（`cloud.getWXContext()` 注入），家庭成员关系判定只在服务端 |
| 模型 | DeepSeek，密钥仅存在于云函数环境变量 |

前置要求：微信开发者工具、一个已认证或个人主体的 AppID、一个云开发环境。

## 自己跑起来

### 1. 导入项目

微信开发者工具 → 导入项目 → 选择本仓库根目录。

改 `project.config.json` 的 `appid` 为自己的小程序 AppID。

### 2. 开通云开发

开发者工具 → 云开发 → 按当前套餐开通 → 记下环境 ID（形如 `cloud1-xxxxxxxx`）。模型和语音请求需核对函数执行时限，3 秒可能不足；不要只按免费额度判断可用性。

写入 `miniprogram/utils/config.js`：

```js
module.exports = {
  envId: 'cloud1-xxxxxxxx',  // 换成自己的
};
```

小程序端必须写明确的 ID，`DYNAMIC_CURRENT_ENV` 只在云函数里有效。

### 3. 建集合

云开发控制台 → 数据库 → 新建以下集合：

| 集合 | 作用 |
|---|---|
| `families` | 家庭 |
| `members` | user_id → family_code，一人一行 |
| `invites` | 邀请码、角色、有效期、使用人 |
| `entries` | 记录正文 |
| `entry_events` | 审计事件（每次修改一条） |
| `entry_types` | 家庭自定义记录类型 |
| `entry_speech_usage` | 可选语音服务的全应用月度调用计数；首次使用时自动创建 |
| `entry_ocr_usage` | 可选 OCR 服务的全应用月度调用计数；首次使用时自动创建 |

数据读写全部走云函数（管理员权限），集合权限保持默认「仅创建者可读写」即可，不要开放给客户端直读。

### 4. 部署云函数

右键 `cloudfunctions/family` → 上传并部署 → **云端安装依赖**。
`entries` 同样操作。

命令行部署（微信开发者工具 CLI），**必须带 `--remote-npm-install`**：

```bash
# macOS 下 CLI 路径，Windows 为安装目录下的 cli.bat
/Applications/wechatwebdevtools.app/Contents/MacOS/cli cloud functions deploy \
  --env cloud1-xxxxxxxx \
  --names family entries \
  --remote-npm-install \
  --project /绝对路径/本仓库
```

注意 `--project` 指向**仓库根目录**（含 `project.config.json` 的那层），不是 `miniprogram/`。

不带这个参数，CLI 只上传 `index.js` + `package.json`，云端不会安装 `wx-server-sdk`，调用直接报 `Cannot find module 'wx-server-sdk'`。

首次部署或刚更新过，函数处于 `Creating` / `Updating` 状态时会报 `FailedOperation.UpdateFunctionCode`，等 15 秒重试即可。

### 5. 配置模型密钥

云开发控制台 → 云函数 → `entries` → 函数配置 → 环境变量，添加：

```
DEEPSEEK_KEY = <你的 DeepSeek API Key>
```

不配置也能用：记录照常保存，只是自动识别和助手不可用。

**不要**把密钥写进源码、前端或数据库。

### 6. 可选语音服务

腾讯云[一句话识别](https://cloud.tencent.cn/document/api/1093/35646)负责语音转文字，DeepSeek 继续负责文字分析，两者分别配置。
只在 `entries` 云函数环境变量设置 `ASR_SECRET_ID` 和 `ASR_SECRET_KEY`，不填入小程序、数据库或源码。
凭据应限制为语音识别所需权限。未配置时，页面明确提示未开通，也不会申请麦克风权限。

按当前[免费额度说明](https://cloud.tencent.cn/document/product/1093/35693)，一句话识别每月有 5000 次免费调用；账号的其他应用会共享额度，超量计费以腾讯云控制台设置为准。
本应用另设全应用每月 1000 次尝试上限，失败也计次；它不能保证同账号其他调用不会产生费用，开通前须核对后付费规则。
录音只临时用于转写，不上传为照片附件；转写文字先留在本机草稿，用户确认才保存。

语音 HTTP 请求设 20 秒总时限，部署前应确认函数执行时限能覆盖该请求及数据库操作，建议至少 30 秒。
当前项目云端仍为 3 秒，尚未开通 ASR，也未做真实录音转写验收，不能将本地代码完成视为语音已可用。

### 7. 可选照片文字识别

默认智能识图复用 `DEEPSEEK_KEY`，使用官方[图片理解接口](https://api-docs.deepseek.com/guides/vision/)的 `deepseek-flash`，不需要另配图片 Key。
照片仅在用户选入时或主动重试时分析，生成本机草稿；采用后才进入正文，确认保存后才入库。
识别失败保留原图和正文；多图逐张处理，结果按照片缓存，未采用结果不会在保存后自动回写。
输入图片及文字使用现有账号的模型额度；仍受云函数执行时限限制，不能把接口已接入视为真机看图已验通。

以下专用 OCR 是可选项：
只在 `entries` 环境变量配置 `OCR_SECRET_ID` / `OCR_SECRET_KEY`，授权范围限制到所需 OCR 接口。
普通截图使用 [GeneralBasicOCR](https://cloud.tencent.com/document/api/866/33526)，手写与小字使用 [GeneralAccurateOCR](https://cloud.tencent.cn/document/product/866/34937)。
按[官方免费额度](https://cloud.tencent.cn/document/product/866/35945)，这两类服务有按月免费资源包；需在控制台确认已开通、资源包到账和后付费设置。
应用内另设共享每月300次尝试上限，不代表账号绝对零费用；失败也计次。图片只在用户点击识别后提交，附原图默认关闭。
OCR 同样受云函数执行时限影响；服务未配置时不会申请相册权限，可先粘贴文字。

### 8. 本轮能力与部署顺序

新客户端的待同步、自然语言查找、专题同步及合并需要同步新版 `entries`，不需要改 `family`。
客户端检查 `scopedAdd` / `naturalSearch` / `topics` / `mergeEntries` 能力标记；旧服务下保留本机内容并明确提示。
语音和专用 OCR 的服务开通、凭据、执行超时与小程序上传发布分别核对，不由代码部署自动完成。图片理解复用现有模型，需新版 `pictureUnderstanding` 能力标记。
未确认的草稿不会自动提交；本机待同步内容不属于云端备份，清理小程序数据前应先完成同步。

## 数据模型要点

- **时间**：事件日期为 `happened_on`，具体时刻存 `at`（`HH:mm`）；无具体时刻时仍显示首次云端保存的 `created_at`，刷新不改变时间。离线补记保留用户选定的日期与时刻，不用联网时刻替代明确的事件时刻。
- **软删除**：`deleted_at` 非空即视为已删，代码里没有任何删除 `entries` 文档的路径。唯一会真删数据的是「移除家庭成员」——删 `members` 那一行，他的历史记录仍在。
- **审计**：`entry_events` 每次修改一条，带 `revision`，用于并发校验和前后对比。
- **幂等**：客户端每次提交带 `requestId`，服务端用它（连同家庭码与 `openid`）哈希派生文档 ID，同一请求重复提交落到同一条记录，不会重复写入；内容有变化则由 `submission_hash` 判定为冲突而不是静默覆盖。

## 隐私设计

- 家庭成员关系**只在服务端判定**：`openid` 由云函数注入，清缓存、换手机都不丢；本地 storage 只做首屏加速。
- 所有 `entries` 操作先校验 `getMember(OPENID)`，没有成员记录直接拒绝。
- 写权限仅 `owner` / `editor`，`viewer` 只读。
- AI 调用发给模型的内容，按用途区分（始终只含当前家庭的数据）：

  | 用途 | 发送内容 |
  |---|---|
  | 识别 `analyze` | 当前这条原文；开启卡片识别时附最近 12 条记录（正文截断 200 字，含日期、时刻、类型） |
  | 助手计划 `assistantPlan` | 请求原文 + 最近 12 条记录 |
  | 成长故事 `assistantStory` | 按日期范围扫描后匹配的记录；超过 60 条时均匀取样到 60 条，只含日期、时刻、正文 |

- **当前界面上不显示「这次发了几条」**。云函数返回里有 `contextCount` / `considered`，但前端还没接。如果你在意这个数字，这是已知的待接入项。
- 模型只提取原文有的事实，不编造地点、时间、用药。

## 已知限制

- **仅微信小程序**，没有独立的 Web 端或 App。
- **未做过大规模测试**：单人家庭自用项目，压力、并发、边界场景未系统验证。
- **模型识别是概率性的**：口语时间、跨夜事件、多事件混写等场景会出错，所以界面保留了「预览 → 确认」一步。
- **动态卡片是声明式数据**，不能执行模型生成的代码。
